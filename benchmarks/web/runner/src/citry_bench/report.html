Framework interaction benchmarks

Local diagnostic results. Bars show medians; circles show individual successful observations. Warmups are excluded. Every axis starts at zero; chart scales differ. Hover or focus an observation for its value. Click a section or chart title to collapse it; the small selects beside a chart title change the same settings as the selects below.

Payload sizes include HTTP bodies and WebSocket bootstrap messages; request and response sizes omit transport headers and socket frame overhead. Final HTML and memory use the common endpoint. Raw observations and failures remain in adjacent JSONL files.

Measurement notes

The common endpoint starts at framework readiness, then schedules a frame, reads board and last-row geometry, and records the next frame. The added ready-to-layout wait is stacked when present; legacy observations without that endpoint keep ready-only bars and show the wait as unavailable. Semantic checks run after the endpoint, so a transient DOM state repaired before it is not independently detected. This is a rendering opportunity, not physical paint.

FCP and LCP are the browser's own first-contentful-paint and largest-contentful-paint times, observed with PerformanceObserver on every initial load and counted from navigation start, the same zero as the stacked bars (the first segment is the wait before the document request). An HTML page can paint before its framework is ready; a page built by JavaScript may first paint only loading text, or nothing until its script runs, so its LCP follows the render. The browser stamps a paint when the frame is shown, so FCP and LCP can fall after the layout endpoint. Chromium reports paint times in coarse steps (whole multiples of 4 ms were observed), so smaller differences are noise. The runner reads the last LCP candidate after the common endpoint and before any click, because Chromium stops reporting LCP at the first input; content that grows after that read is not counted. Values the browser did not report are shown as unavailable, never as zero.

First and second page loads share an application and browser process but use fresh browser contexts and scenario sessions. Latency-stack residuals include transport and unmeasured server work. Memory observer overhead has not been calibrated; these are diagnostic results, not publication rankings.
