Diagnostic reference

Every error and warning Citry reports has a code, such as citry.template.unknown-variable. The editor shows it next to the message, and citry check prints it with each finding. Find the code below to see what went wrong and how to fix it.

The code always names the same mistake in every tool: the editor, citry check, citry format, and the template parser. The message can add details, such as the name you misspelled.

Some rules can be made stricter or turned off. Those entries say "Your application can change this severity". For the template lint rules, see Template linting.

Codes that start with citry.python. or citry.typescript. come from the Python and TypeScript type checkers. They are listed at the end of this page.

citry.parse.syntax

Invalid template syntax. The template has a syntax mistake, such as an unclosed element or an unfinished expression. Citry cannot read the template, so it does not render.

Example: Unclosed element

<section>
  <p>Hello</p>

Fix: Correct the template at the reported position. The message says what the parser expected there.

When this appears: The parser finds malformed markup, an incomplete expression, or another syntax error. Only the first syntax error in a template is reported.

Default severity: error. Reported by: template parser APIs, citry format, citry check, citry-lsp.

citry.parse.value

Invalid template value. Citry was given a value it cannot parse as a template. This is usually not a mistake in your template text.

Fix: If an extension adds its own template syntax, update it or report the message to its authors. Otherwise, report the message as a Citry bug.

When this appears: A parser API receives a value it cannot turn into template source, for example when an extension that adds its own template syntax reports positions that do not fit the template.

Default severity: error. Reported by: template parser APIs, citry format, citry check, citry-lsp.

citry.parse.configuration

Template parser setup failed. Citry could not set up the template parser for your application, so it cannot check this template.

Fix: Read the message for the rule that failed, and fix the application or extension that defines it.

When this appears: The tag rules that your application or its extensions add to the parser cannot be built or applied.

Default severity: error. Reported by: citry check, citry-lsp.

citry.template.unknown-variable

Unknown template variable. A template reads a variable that nothing provides, often because of a typo. Rendering then fails with a KeyError.

Messages:

  • Closed template data:

    Template variable '{name}' is not available in this template.

  • Template data allows extra names:

    Template variable '{name}' is not declared. It may be supplied dynamically.

  • Template data could not be inspected:

    Template variable '{name}' is not declared. Citry could not determine whether it is supplied dynamically.

Example: Unknown name in an interpolation

<p>{{ missing_name }}</p>

Example: Unknown name in a dynamic attribute

<div c-title="missing_name"></div>

Fix: Correct the name, or add it to the data that template_data() returns. If another integration provides it, declare it in template_variables, or change rule_unknown_template_variable.

When this appears: A name in {{ ... }} or in a c-* attribute is not in the component's template data, a c-for or c-fill binding around it, template_globals, or the declared template_variables. In a template that several components share, every one of them must provide the name.

Default severity: error. Your application can change this severity. Reported by: citry check, citry-lsp.

citry.template.unknown-component

Unknown component. A component tag names a component that your application does not register, often because of a typo. The template fails to render.

Message:

Component <{tag}> is not registered.

Example: Unregistered component tag

<c-missing-card />

Fix: Correct the tag name, or register the component with the application that Citry loaded.

When this appears: A <c-*> tag names no component in the selected application or library, counting built-in names and aliases.

Default severity: error. Reported by: citry check, citry-lsp.

citry.template.marker-name-invalid

Invalid <c-mark> tag. A <c-mark> tag, which marks part of a component that an event handler can replace, has no usable name, an extra attribute, or content it does not accept.

Messages:

  • dynamic:

    Marker name must be a static literal.

  • invalid:

    Marker name must match [A-Za-z][A-Za-z0-9_-]*.

  • missing:

    Marker requires a literal name attribute.

  • extra:

    Marker accepts only its name attribute.

  • named_fill:

    Marker accepts only its default slot.

Fix: Give the marker one literal name that starts with a letter and contains only letters, digits, _ or -. Remove other attributes and named fills.

When this appears: A <c-mark> tag has no name attribute, a dynamic or invalid name, any other attribute, or a named fill.

Default severity: error. Reported by: citry check, citry-lsp.

citry.template.alpine-attribute

Alpine attribute on an HTML element. An HTML element still has an Alpine x-* attribute, such as x-data or x-on:click. Citry uses Vue, so nothing reads it and it does nothing.

Message:

'{name}' is an Alpine attribute. Citry uses Vue, so nothing reads it. Replace it with its Vue form, or set rule_alpine_attribute to 'ignore' if a library on the page reads '{name}'.

Example: Alpine state on an element

<div x-data="{ open: false }">
  <button x-on:click="open = !open">Menu</button>
</div>

Fix: Move the state into js_data() or $component, and write the listener in its Vue form, such as @click. If another library on the page reads x-* attributes, set rule_alpine_attribute to "ignore".

When this appears: An Alpine directive name, such as x-data, x-on:click, or x-intersect, sits on an HTML element or <c-element>, including inside nested templates. Other x-* names, such as x-webkit-airplay, are ordinary HTML. Component tags are not checked, because an x-* attribute there is a Python keyword argument. x-cloak is reported as citry.template.alpine-cloak.

Default severity: warning. Your application can change this severity. Reported by: citry check, citry-lsp.

citry.template.alpine-cloak

x-cloak hides an element for good. An HTML element still has x-cloak. Nothing removes it, so a [x-cloak] CSS rule hides the element for good.

Message:

Nothing in Citry removes 'x-cloak', so a '[x-cloak]' CSS rule keeps this element hidden. Delete 'x-cloak' and its '[x-cloak]' rule; the server-rendered HTML already shows the content.

Example: Leftover x-cloak

<div x-cloak>{{ message }}</div>

Fix: Delete x-cloak and its [x-cloak] CSS rule. The HTML from the server already shows the content.

When this appears: x-cloak, in any letter case, sits on an HTML element or <c-element>, including inside nested templates. Component tags are not checked.

Default severity: error. Your application can change this severity. Reported by: citry check, citry-lsp.

citry.template.invalid-attribute-value

HTML attribute value the browser does not accept. An HTML attribute that accepts only certain keywords, such as draggable or type, has another value. The browser ignores it or falls back to a default, with no error.

Messages:

  • default:

    '{value}' is not a valid value for '{attribute}' on <{element}>. Valid values: {allowed}.

  • suggestion:

    '{value}' is not a valid value for '{attribute}' on <{element}>. Did you mean '{suggestion}'? Valid values: {allowed}.

  • empty:

    '{attribute}' on <{element}> needs a value. Valid values: {allowed}.

  • target:

    '{value}' is not a valid value for '{attribute}' on <{element}>. A name that starts with '_' must be one of: {allowed}.

  • frame-name:

    '{value}' is not a valid value for '{attribute}' on <{element}>. A frame name cannot start with '_'.

  • pragma:

    '{value}' is not a pragma browsers act on in '{attribute}' on <{element}>. If it is an HTTP header, send it in the HTTP response instead. Valid values: {allowed}.

Example: A misspelled keyword

<div draggable="treu">Drag me</div>

Example: An input type the browser does not know

<input type="datetime" name="start">

Fix: Use one of the valid values the message lists. If a script on the page reads its own values from the attribute, set rule_invalid_attribute_value to "ignore" for that component.

When this appears: The value is not one of the keywords the HTML Standard lists for that attribute on that element. Letter case does not matter, except for list markers in type on <ol> and <li>. A Vue binding whose value is one JavaScript string, such as :dir="'rtl'", is checked too. Other bound values, component tags, <c-element>, custom elements, elements inside <svg> or <math>, and attributes that take a list of words, such as rel, are not checked.

Default severity: warning. Your application can change this severity. Reported by: citry check, citry-lsp.

citry.js-data.unsupported-type

JsData field is not a JSON type. A JsData field has a type that cannot be sent to the browser as JSON, such as a set or a date. Editor help treats the value as any.

Message:

JsData field '{name}' is not a clean JSON value: {detail}. Browser tooling will treat its type as unknown.

Example: Unsupported set value

class Card(Component):
    class JsData:
        selected_ids: set[int]

Fix: Convert the value to JSON-friendly data in js_data(), such as a list, a string, or a dict of plain values, and change the JsData annotation to match.

When this appears: A declared or inferred JsData field has a type that strict JSON cannot carry, such as bytes, a set, a callable, a date or time, or a whole class instance.

Default severity: warning. Reported by: citry check, citry-lsp.

citry.js-data.public-name-collision

JsData field conflicts with a public instance name. A JsData field has the same name as something already on the component instance in the browser, such as a prop, a method, or a name Vue reserves.

Messages:

  • default:

    JsData field '{name}' conflicts with a reserved or component-defined public instance name.

  • conditional:

    JsData field '{name}' conflicts with a reserved or component-defined public instance name when supplied.

Fix: Rename the JsData field, or rename the Vue Options entry it collides with.

When this appears: A JsData field that Citry can see in the source uses a reserved browser name or the name of a Vue Options entry, such as a prop, method, or computed value.

Default severity: error. Reported by: citry-lsp.

citry.vue.unknown-variable

Unknown Vue variable. A Vue expression reads a name the component does not send to the browser, often because of a typo. Vue shows nothing, or the expression fails in the browser.

Messages:

  • default:

    Vue variable '{name}' is not available in this component.

  • python:

    Vue variable '{name}' is not available in this component. '{name}' is a Python variable here, which the browser never sees; pass its value with a c- attribute or loop with Vue's v-for.

Example: Unknown name in a Vue expression

<button :disabled="submitting1">Save</button>

Fix: Correct the name, or send the value from js_data(). If it is a Python variable, pass it with a c- attribute instead. Declare names that come from outside Citry in vue_variables, or change rule_unknown_vue_variable.

When this appears: A name in a Vue expression is not a JsData or js_data() key, a v-for or slot alias around it, a Vue or Citry helper, a browser global, or a declared vue_variables entry.

Default severity: error. Your application can change this severity. Reported by: citry check, citry-lsp.

citry.vue.python-variable

Python variable read by a Vue expression. A Vue expression reads a Python c-for or c-fill variable. The browser never sees that variable, so the value is missing, or Vue shows a different browser value with the same name.

Messages:

  • default:

    Vue reads '{name}' from browser state, but '{name}' is a Python variable here. Pass its value with a c- attribute or loop with Vue's v-for instead.

  • attribute:

    Vue reads '{name}' from browser state, but '{name}' is a Python variable here. Use c-{attribute}="{name}" to pass the Python value.

  • browser:

    Vue reads the component's browser value '{name}' here, not the Python loop or slot variable '{name}'. Pass the Python value with a c- attribute, or rename one of them.

  • browser-attribute:

    Vue reads the component's browser value '{name}' here, not the Python loop or slot variable '{name}'. Use c-{attribute}="{name}" for the Python value, or rename one of them.

Example: Python loop variable in a Vue binding

<li c-for="item in items" :title="item"></li>

Fix: Pass the Python value with a c- attribute, such as c-title="item" instead of :title="item", or loop with Vue's v-for. If a browser value has the same name, rename one of them.

When this appears: A Vue expression inside a c-for loop or c-fill binding reads the Python variable, and no Vue v-for or slot alias of that name is around it. When Citry knows every name the component sends to the browser and the name is not among them, it reports citry.vue.unknown-variable instead, unless that rule is set to ignore.

Default severity: warning. Your application can change this severity. Reported by: citry check, citry-lsp.

citry.component-js.unknown-variable

Unknown component JavaScript variable. Code inside $component reads a name that is not declared there, often a callback value you forgot to destructure. It fails in the browser.

Message:

Component JavaScript variable '{name}' is not defined.

Example: Undeclared name in a callback

$component(({ component }) => {
  component.ready = settings.ready;
});

Fix: Declare or destructure the name, or read the value from the component instance. If a project script defines it as a global, declare it in component_js_globals, or change rule_unknown_component_js_variable.

When this appears: A name inside a $component initializer is not declared in that code, destructured from the callback's argument, a JavaScript or browser global, or a declared component_js_globals entry.

Default severity: error. Your application can change this severity. Reported by: citry check, citry-lsp.

citry.component-js.unknown-member

Unknown component instance member. Component JavaScript reads this.<name> or component.<name>, and the component has no member with that name, often because of a typo. The value is undefined in the browser.

Message:

Component instance member '{name}' is not defined by this component.

Example: Misspelled js_data() key in a callback

$component(({ component }) => {
  console.log(component.missing_field);
});

Fix: Correct the name, or define it on the component. A plugin that adds a property to every component should give it a $ prefix, such as $api.

When this appears: The name is not a js_data() key, prop, data() key, setup binding, method, computed value, or injection. Citry checks only when it can see every js_data() key and every Vue Options section in the source. It skips names that start with $ or _, bracket reads such as component[key], and code that uses mixins, extends, Object.assign, a class, or computed member names.

Default severity: error. Your application can change this severity. Reported by: citry check, citry-lsp.

citry.browser.invalid-state-binding-target

Invalid State binding target. A :c-* State binding is on an element that has no value to bind, such as a <div>, or an input type that cannot hold one, such as a file input.

Example: Binding on a non-control element

<head :c-query></head>

Fix: Bind a form control that holds a value, such as <input>, <select>, or <textarea>. On a custom element, name its update event with .on:<event>. To react to an event on another element, use an @c-* binding instead.

When this appears: The element or input type cannot hold a bound value, or does not support the binding's direction or update event.

Default severity: error. Reported by: citry check, citry-lsp.

citry.browser.unknown-state-field

Unknown State binding field. A :c-* State binding names a field the component's State does not have, often because of a typo.

Message:

State field '{name}' is not a public field of this component.

Example: Unknown field in a State binding

<input :c-missing_field.debounce="refresh">

Fix: Correct the field name, or add the field to the component's State class.

When this appears: A :c-* binding names a field that is not a public field of the component's State class. Bindings whose component or State class Citry cannot determine are not checked.

Default severity: error. Reported by: citry check, citry-lsp.

citry.browser.unknown-server-event

Unknown server event. Browser code names a server event that the component has no handler for, often because of a typo.

Message:

Server event '{name}' is not declared by this component.

Example: Unknown literal event

<button @click="sendEvent('missing')">Run</button>

Example: Unknown declarative handler

<button @c-click="missing">Run</button>

Example: Unknown loading handler

<span v-show="$loading('missing')">Saving</span>

Fix: Correct the name, or add a public method with that name to the component's Events class.

When this appears: A template or component JavaScript calls sendEvent, $sendEvent, $loading, or $error with a string that names no handler, or an @c-* binding names no handler.

Default severity: error. Reported by: citry check, citry-lsp.

citry.browser.undeclared-emit

Undeclared emitted event. Browser code emits a Vue event that the component's emits option does not list, often because of a typo. Parents listening for the declared name never hear it.

Message:

Event '{name}' is not declared in this component's emits option.

Example: Misspelled event in a method

$component({
  emits: ['drop-task'],
  methods: {
    drop() { this.$emit('drop-tsak'); },
  },
});

Example: Undeclared event in the template

<button @click="$emit('close')">Close</button>

Fix: Correct the event name, or add it to emits.

When this appears: this.$emit, component.$emit, or $emit in the component's template uses a name that emits does not list and no on<Event> prop declares. Citry checks only when emits is an array of strings or an object with plain keys. A component without emits may emit any name, as in Vue.

Default severity: error. Reported by: citry check, citry-lsp.

citry.browser.undeclared-component-event

Listener for an event the child component does not declare. A template listens on a child component for an event the child does not declare, often because of a typo. The listener usually never runs.

Message:

Component '{component}' does not declare event '{name}' in its emits option.

Example: Misspelled child event

<c-Lane @drop-tsak="moveTask($event)"></c-Lane>

Fix: Correct the event name, or add it to the child's emits.

When this appears: An @name or v-on:name listener on a component tag names an event that the child's emits does not list and no on<Event> prop accepts. Vue then passes the listener to the child's root element, where it runs only for a DOM event of that name. Only names with a hyphen, a colon, or an uppercase letter are reported, because a plain lowercase name such as click is usually a DOM event. Citry checks only when the child's emits is an array of strings or an object with plain keys.

Default severity: warning. Reported by: citry check, citry-lsp.

citry.browser.missing-component-prop

Missing required Vue prop. A component tag leaves out a Vue prop that the child component marks as required.

Message:

Required Vue prop '{name}' is missing for <{tag}>.

Example: Missing required prop

<c-card />

Fix: Pass the prop on the tag, such as :count="total".

When this appears: A registered <c-*> tag has no Vue binding for a prop the child declares with required: true, and no spread binding could supply it.

Default severity: error. Reported by: citry check, citry-lsp.

citry.browser.incompatible-component-prop

Incompatible Vue prop. A Vue prop on a component tag gets a value of a type the child component does not accept.

Message:

Vue prop '{name}' expects {expected}, but this binding is {actual}.

Example: Wrong literal type

<c-card :count="'many'" />

Fix: Pass a value of the type the child declares, or change the child's prop type.

When this appears: A :prop or v-bind:prop value on a component tag has a type Citry knows, from a literal, JsData, or a loop binding, and the child's declared Vue prop type does not accept it.

Default severity: error. Reported by: citry check, citry-lsp.

citry.check.template-declaration

Template declaration unavailable. citry check could not read a component's template or template_file, for example because computing it raised an error.

Message:

Citry could not inspect this component's template declaration: {detail}

Fix: Read the error in the message and fix the declaration or the code it runs.

When this appears: Reading the component's template or template_file declaration raises an error, or Citry cannot tell which declaration applies.

Default severity: error. Reported by: citry check.

citry.check.template-language-unsupported

Unsupported template language. The component sets template_lang to another template language. citry check reads only Citry templates, so it skipped this one.

Message:

Citry cannot check template_lang with a {type} value. This template was skipped.

Fix: Nothing to fix if the other language is intended. Check that template with that language's own tools.

When this appears: A component's template_lang is not None.

Default severity: error. Reported by: citry check.

citry.check.template-value-invalid

Invalid template declaration value. A component's template or template_file has a value of the wrong type, so citry check skipped it.

Messages:

  • Inline template:

    Component.template must be a string. This template was skipped.

  • Template file:

    Component.template_file must be a string or Path. This template was skipped.

Example: Non-string inline template

class Card(Component):
    template = build_template()

Fix: Set template to a string, or template_file to a string or Path.

When this appears: Component.template is not a string, or Component.template_file is neither a string nor a pathlib.Path.

Default severity: error. Reported by: citry check.

citry.check.template-file-not-found

Template file not found. The file named in template_file does not exist in any place Citry looks.

Message:

Template file '{path}' was not found. Searched: {locations}.

Example: Missing template file

class Card(Component):
    template_file = "missing.html"

Fix: Correct the path, or move the file to one of the searched locations the message lists.

When this appears: template_file points to a path that is not in the component's directory or any configured template directory.

Default severity: error. Reported by: citry check.

citry.check.template-file-unreadable

Template file could not be read. The template file exists, but Citry could not open it or read it as UTF-8 text.

Message:

Citry could not read this template file: {detail}

Fix: Check the file's permissions, and save it as UTF-8.

When this appears: Citry finds the template_file but cannot open it, or it is not valid UTF-8.

Default severity: error. Reported by: citry check.

citry.check.template-namespace-unavailable

Template variables unavailable. citry check could not work out which variables a component's template receives, so it cannot check them.

Message:

Citry could not inspect this template's variables: {detail}

Fix: Read the error in the message and fix the template data declaration or the code it runs.

When this appears: Reading the component's declared or inferred template data raises an error.

Default severity: error. Reported by: citry check.

citry.check.python-source-unreadable

Python source could not be analyzed. A Python file could not be read or parsed, so its components were not checked.

Message:

Citry could not analyze this Python source: {detail}

Fix: Fix the Python syntax error or encoding problem in the file the message names.

When this appears: citry check --static reaches a Python file it cannot read, decode, or parse.

Default severity: error. Reported by: citry check.

citry.i18n.catalog-invalid

Invalid Fluent catalog source. A messages block or Fluent catalog file has invalid Fluent syntax or another translation source mistake.

Fix: Correct the Fluent source at the reported position. The message says what is wrong.

When this appears: A messages block or catalog file has invalid Fluent syntax, an unsupported @param type, or another source error.

Default severity: error. Reported by: citry check, citry-lsp.

citry.i18n.unknown-message

Unknown i18n message. Code asks for a translation message that no catalog defines, often because of a typo in the message ID.

Fix: Correct the message ID, or add the message to the component's messages or a catalog.

When this appears: A tr() call, <c-trans> tag, $c-tr binding, or browser bind() call with a literal ID names a message or attribute that no component or configured catalog package defines.

Default severity: error. Reported by: citry check, citry-lsp.

citry.i18n.argument-invalid

Invalid i18n argument. A translation call passes the wrong inputs: a missing, extra, or mistyped argument, an unknown format profile, or wrong <c-trans> values or fills.

Fix: Match the arguments to the message's @param declarations, which hover shows, or correct the profile name.

When this appears: A literal i18n call or $c-tr binding is malformed, its message inputs do not match the message's @param declarations, it names an unknown formatter or parser profile, or a <c-trans> tag supplies the wrong values or fills.

Default severity: error. Reported by: citry check, citry-lsp.

citry.i18n.missing-param-type

Message variable without a type. A message uses a variable that has no # @param comment, so Citry cannot check the type of the value that callers pass in.

Fix: Add a comment such as # @param {str} $name above the message, naming the type the variable really takes. Set rule_i18n_missing_param_type to "error" to make a missing type fail catalog compilation, or to "ignore" to hide this warning.

When this appears: A source-language message uses a variable such as { $name } in its value or an attribute, has no # @param comment declaring its type, and rule_i18n_missing_param_type is "warning". A variable used in a selector or a formatting function without a type fails catalog compilation and is reported as citry.i18n.catalog-invalid.

Default severity: warning. Your application can change this severity. Reported by: citry check.

citry.i18n.cross-language-fallback

Text from a fallback language. A translation is missing for some locales, so this text appears in another language there. The page still renders, but the text sits inside an element marked with the requested language, so a screen reader may read it with the wrong pronunciation.

Fix: Add the missing translations; the i18n coverage command lists them. To show fallback text with its own language, call self.i18n.resolve() and put its locale and direction on an element, as the i18n guide's Language direction and accessibility page shows. Set rule_i18n_cross_language_fallback to "error" to require complete translations, or to "ignore" to hide this warning.

When this appears: A tr() call or self.i18n.tr() call with a literal message ID, or a message listed in Component.I18n.client_messages, has no translation in some selectable locale and resolves to another locale through the configured fallbacks or the message's source locale.

Default severity: warning. Your application can change this severity. Reported by: citry check.

citry.i18n.rich-message-fallback

Rich message without a translation. A <c-trans> message has no translation in some locale. Rendering it in that locale raises I18nRuntimeUnavailableError, because <c-trans> adds no element that could mark text from a fallback language.

Fix: Add a translation for each locale the finding lists. Plain text messages may fall back; only <c-trans> needs every translation.

When this appears: A <c-trans> tag names a message or attribute that has no translation in some selectable locale, so it would resolve to another locale through the configured fallbacks or the message's source locale.

Default severity: error. Reported by: citry check.

citry.i18n.client-message-invalid

Unknown client i18n message. Component.I18n.client_messages names a message that does not exist, so the browser cannot load it.

Fix: Correct the name in client_messages, or add the message.

When this appears: Component.I18n.client_messages names a message ID that no component or configured catalog package defines.

Default severity: error. Reported by: citry check.

citry.format.syntax

Invalid template syntax. The template has a syntax error, so the formatter left it unchanged.

Fix: Fix the syntax error, then format again.

When this appears: A format command receives a template with a Citry syntax error.

Default severity: error. Reported by: citry format, citry-lsp, the Citry VS Code extension.

citry.format.suppression

Invalid formatter directive. A fmt: on, fmt: off, or fmt: skip comment has no matching partner or sits where it cannot apply.

Example: Unmatched formatter enable directive

{# fmt: on #}
<div></div>

Fix: Pair each fmt: off with a fmt: on in the same scope, or remove the stray directive.

When this appears: A formatter directive has no valid scope at the place it is written, such as a fmt: on without an earlier fmt: off.

Default severity: error. Reported by: citry format, citry-lsp, the Citry VS Code extension.

citry.format.invariant

Formatter safety check failed. The formatter's own safety check failed, so it refused to change the file. Your template is not at fault.

Fix: The file is unchanged. Report the template and message as a Citry bug.

When this appears: The formatted result fails one of Citry's safety checks, for example formatting it a second time would change it again.

Default severity: error. Reported by: citry format, citry-lsp, the Citry VS Code extension.

citry.format.unsupported

Formatting shape unsupported. The template is valid, but the formatter cannot rewrite this shape safely, so it left it unchanged.

Fix: Nothing to fix. Format that part by hand, or wrap it in fmt: off and fmt: on.

When this appears: The template's structure is outside what the formatter can rewrite.

Default severity: error. Reported by: citry format, citry-lsp, the Citry VS Code extension.

citry.format.provider-invalid

Embedded formatter returned invalid output. The JavaScript or CSS formatter returned a change that does not fit the code it was asked to format, so Citry discarded it.

Fix: The file is unchanged. Try another formatter for that language, or report the message.

When this appears: An external JavaScript or CSS formatter returns an edit outside the region Citry sent it.

Default severity: error. Reported by: citry format, citry-lsp, the Citry VS Code extension.

citry.format.embedded-suppressed

Embedded formatting suppressed. A fmt: off or fmt: skip comment kept a JavaScript or CSS region unformatted, as requested.

Fix: Nothing to fix. Remove the directive if you want the region formatted.

When this appears: A fmt: off or fmt: skip directive covers an embedded JavaScript or CSS region.

Default severity: information. Reported by: citry format, citry-lsp, the Citry VS Code extension.

citry.format.embedded-language-unsupported

Embedded language unsupported. A <script> or <style> region declares a language Citry has no formatter for, so it was left unchanged.

Fix: Nothing to fix. Format that region with its own tools.

When this appears: An embedded script or style region declares a language that no Citry formatter handles.

Default severity: warning. Reported by: citry format, citry-lsp, the Citry VS Code extension.

citry.format.embedded-interpolation-unsupported

Embedded interpolation unsupported. A JavaScript or CSS region contains Citry interpolation, such as {{ title }}, so it was left unchanged.

Example: Citry interpolation inside JavaScript

<script>
  const title = "{{ title }}";
</script>

Fix: Pass the value through js_data() or css_data() instead of interpolating it, or leave the region unformatted.

When this appears: An embedded JavaScript or CSS region contains Citry interpolation, which an external formatter cannot handle safely.

Default severity: warning. Reported by: citry format, citry-lsp, the Citry VS Code extension.

citry.format.provider-unavailable

Embedded formatter unavailable. No JavaScript or CSS formatter answered, so that region was left unchanged.

Fix: In VS Code, check that Prettier for VS Code is installed and enabled for the language, or disable it so Citry uses its own copy of Prettier.

When this appears: Citry asks the editor to format embedded JavaScript or CSS, and no installed formatter returns an edit.

Default severity: warning. Reported by: citry format, citry-lsp, the Citry VS Code extension.

citry.format.host-syntax

Invalid Python host syntax. The Python file has a syntax error, so Citry could not find the component strings to format.

Fix: Fix the Python syntax error, then format again.

When this appears: A format command targets a Python file that is not valid Python.

Default severity: error. Reported by: citry format, citry-lsp, the Citry VS Code extension.

citry.format.ineligible

Document is not eligible for formatting. The file or cursor position is not inside a Citry template, script, or style, so there is nothing to format.

Fix: Place the cursor inside a template, js, or css string, or open the template file itself.

When this appears: Citry cannot tell that the document or cursor position belongs to a template, js, or css string, or a standalone Citry template.

Default severity: error. Reported by: citry format, citry-lsp, the Citry VS Code extension.

citry.format.stale-document

Document changed during formatting. The document changed while Citry was formatting it, so the result was discarded.

Fix: Run the format command again.

When this appears: The document changes after Citry prepares the edit and before the editor applies it.

Default severity: error. Reported by: citry-lsp, the Citry VS Code extension.

citry.format.cancelled

Formatting cancelled. Formatting was cancelled before Citry applied it.

Fix: Nothing to fix. Run the format command again if needed.

When this appears: The editor or you cancel a format request before Citry applies its edits.

Default severity: information. Reported by: the Citry VS Code extension.

Codes from the type checkers

citry.python.*

Reported by: ty. Python type errors in template expressions and c-* values, such as a value of the wrong type for a component input. They come from ty, the Python type checker Citry runs. The part after citry.python. is ty's rule name, and the message is ty's.

citry.typescript.*

Reported by: TypeScript. TypeScript errors in component JavaScript and Vue expressions, such as a wrong argument type, an unknown member, or a wrong number of arguments. The part after citry.typescript. is TypeScript's error number, such as ts2322, and the message is TypeScript's. When one of Citry's own diagnostics already reports the same mistake, Citry shows only its own.
