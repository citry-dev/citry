# Diagnostic reference

Every error and warning Citry reports has a code, such as
`citry.template.unknown-variable`. The editor shows it next to the message,
and `citry check` prints it with each finding. Find the code below to see what
went wrong and how to fix it.

The code always names the same mistake in every tool: the editor,
`citry check`, `citry format`, and the template parser. The message can add details,
such as the name you misspelled.

Some rules can be made stricter or turned off. Those entries say "Your
application can change this severity". For the template lint rules, see
[Template linting](/v/0.6.0/ide/template-linting/#change-how-strict-a-rule-is).

Codes that start with `citry.python.` or `citry.typescript.` come from the
Python and TypeScript type checkers. They are listed at the end of this page.

<section class="diagnostic-reference" aria-labelledby="citry.parse.syntax"><h2 id="citry.parse.syntax" class="toc-heading"><code>citry.parse.syntax</code></h2><p><strong>Invalid template syntax.</strong> The template has a syntax mistake, such as an unclosed element or an unfinished expression. Citry cannot read the template, so it does not render.</p><div class="diagnostic-example"><p><strong>Example: Unclosed element</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;section&gt;
  &lt;p&gt;Hello&lt;/p&gt;</code></pre></div></div><p><strong>Fix:</strong> Correct the template at the reported position. The message says what the parser expected there.</p><p><strong>When this appears:</strong> The parser finds malformed markup, an incomplete expression, or another syntax error. Only the first syntax error in a template is reported.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> template parser APIs, <code>citry format</code>, <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.parse.value"><h2 id="citry.parse.value" class="toc-heading"><code>citry.parse.value</code></h2><p><strong>Invalid template value.</strong> Citry was given a value it cannot parse as a template. This is usually not a mistake in your template text.</p><p><strong>Fix:</strong> If an extension adds its own template syntax, update it or report the message to its authors. Otherwise, report the message as a Citry bug.</p><p><strong>When this appears:</strong> A parser API receives a value it cannot turn into template source, for example when an extension that adds its own template syntax reports positions that do not fit the template.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> template parser APIs, <code>citry format</code>, <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.parse.configuration"><h2 id="citry.parse.configuration" class="toc-heading"><code>citry.parse.configuration</code></h2><p><strong>Template parser setup failed.</strong> Citry could not set up the template parser for your application, so it cannot check this template.</p><p><strong>Fix:</strong> Read the message for the rule that failed, and fix the application or extension that defines it.</p><p><strong>When this appears:</strong> The tag rules that your application or its extensions add to the parser cannot be built or applied.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.unknown-variable"><h2 id="citry.template.unknown-variable" class="toc-heading"><code>citry.template.unknown-variable</code></h2><p><strong>Unknown template variable.</strong> A template reads a variable that nothing provides, often because of a typo. Rendering then fails with a KeyError.</p><p><strong>Messages:</strong></p><ul class="diagnostic-messages"><li class="diagnostic-message"><p><strong>Closed template data:</strong></p><div class="highlight"><pre><code>Template variable &#39;{name}&#39; is not available in this template.</code></pre></div></li><li class="diagnostic-message"><p><strong>Template data allows extra names:</strong></p><div class="highlight"><pre><code>Template variable &#39;{name}&#39; is not declared. It may be supplied dynamically.</code></pre></div></li><li class="diagnostic-message"><p><strong>Template data could not be inspected:</strong></p><div class="highlight"><pre><code>Template variable &#39;{name}&#39; is not declared. Citry could not determine whether it is supplied dynamically.</code></pre></div></li></ul><div class="diagnostic-example"><p><strong>Example: Unknown name in an interpolation</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;p&gt;{{ missing_name }}&lt;/p&gt;</code></pre></div></div><div class="diagnostic-example"><p><strong>Example: Unknown name in a dynamic attribute</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;div c-title=&#34;missing_name&#34;&gt;&lt;/div&gt;</code></pre></div></div><p><strong>Fix:</strong> Correct the name, or add it to the data that template_data() returns. If another integration provides it, declare it in template_variables, or change rule_unknown_template_variable.</p><p><strong>When this appears:</strong> A name in {{ ... }} or in a c-* attribute is not in the component&#39;s template data, a c-for or c-fill binding around it, template_globals, or the declared template_variables. In a template that several components share, every one of them must provide the name.</p><p><strong>Default severity:</strong> <code>error</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.unknown-component"><h2 id="citry.template.unknown-component" class="toc-heading"><code>citry.template.unknown-component</code></h2><p><strong>Unknown component.</strong> A component tag names a component that your application does not register, often because of a typo. The template fails to render.</p><p><strong>Message:</strong></p><div class="highlight"><pre><code>Component &lt;{tag}&gt; is not registered.</code></pre></div><div class="diagnostic-example"><p><strong>Example: Unregistered component tag</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;c-missing-card /&gt;</code></pre></div></div><p><strong>Fix:</strong> Correct the tag name, or register the component with the application that Citry loaded.</p><p><strong>When this appears:</strong> A &lt;c-*&gt; tag names no component in the selected application or library, counting built-in names and aliases.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.marker-name-invalid"><h2 id="citry.template.marker-name-invalid" class="toc-heading"><code>citry.template.marker-name-invalid</code></h2><p><strong>Invalid &lt;c-mark&gt; tag.</strong> A &lt;c-mark&gt; tag, which marks part of a component that an event handler can replace, has no usable name, an extra attribute, or content it does not accept.</p><p><strong>Messages:</strong></p><ul class="diagnostic-messages"><li class="diagnostic-message"><p><strong>dynamic:</strong></p><div class="highlight"><pre><code>Marker name must be a static literal.</code></pre></div></li><li class="diagnostic-message"><p><strong>invalid:</strong></p><div class="highlight"><pre><code>Marker name must match [A-Za-z][A-Za-z0-9_-]*.</code></pre></div></li><li class="diagnostic-message"><p><strong>missing:</strong></p><div class="highlight"><pre><code>Marker requires a literal name attribute.</code></pre></div></li><li class="diagnostic-message"><p><strong>extra:</strong></p><div class="highlight"><pre><code>Marker accepts only its name attribute.</code></pre></div></li><li class="diagnostic-message"><p><strong>named_fill:</strong></p><div class="highlight"><pre><code>Marker accepts only its default slot.</code></pre></div></li></ul><p><strong>Fix:</strong> Give the marker one literal name that starts with a letter and contains only letters, digits, _ or -. Remove other attributes and named fills.</p><p><strong>When this appears:</strong> A &lt;c-mark&gt; tag has no name attribute, a dynamic or invalid name, any other attribute, or a named fill.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.alpine-attribute"><h2 id="citry.template.alpine-attribute" class="toc-heading"><code>citry.template.alpine-attribute</code></h2><p><strong>Alpine attribute on an HTML element.</strong> An HTML element still has an Alpine x-* attribute, such as x-data or x-on:click. Citry uses Vue, so nothing reads it and it does nothing.</p><p><strong>Message:</strong></p><div class="highlight"><pre><code>&#39;{name}&#39; is an Alpine attribute. Citry uses Vue, so nothing reads it. Replace it with its Vue form, or set rule_alpine_attribute to &#39;ignore&#39; if a library on the page reads &#39;{name}&#39;.</code></pre></div><div class="diagnostic-example"><p><strong>Example: Alpine state on an element</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;div x-data=&#34;{ open: false }&#34;&gt;
  &lt;button x-on:click=&#34;open = !open&#34;&gt;Menu&lt;/button&gt;
&lt;/div&gt;</code></pre></div></div><p><strong>Fix:</strong> Move the state into js_data() or $component, and write the listener in its Vue form, such as @click. If another library on the page reads x-* attributes, set rule_alpine_attribute to &#34;ignore&#34;.</p><p><strong>When this appears:</strong> An Alpine directive name, such as x-data, x-on:click, or x-intersect, sits on an HTML element or &lt;c-element&gt;, including inside nested templates. Other x-* names, such as x-webkit-airplay, are ordinary HTML. Component tags are not checked, because an x-* attribute there is a Python keyword argument. x-cloak is reported as citry.template.alpine-cloak.</p><p><strong>Default severity:</strong> <code>warning</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.alpine-cloak"><h2 id="citry.template.alpine-cloak" class="toc-heading"><code>citry.template.alpine-cloak</code></h2><p><strong>x-cloak hides an element for good.</strong> An HTML element still has x-cloak. Nothing removes it, so a [x-cloak] CSS rule hides the element for good.</p><p><strong>Message:</strong></p><div class="highlight"><pre><code>Nothing in Citry removes &#39;x-cloak&#39;, so a &#39;[x-cloak]&#39; CSS rule keeps this element hidden. Delete &#39;x-cloak&#39; and its &#39;[x-cloak]&#39; rule; the server-rendered HTML already shows the content.</code></pre></div><div class="diagnostic-example"><p><strong>Example: Leftover x-cloak</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;div x-cloak&gt;{{ message }}&lt;/div&gt;</code></pre></div></div><p><strong>Fix:</strong> Delete x-cloak and its [x-cloak] CSS rule. The HTML from the server already shows the content.</p><p><strong>When this appears:</strong> x-cloak, in any letter case, sits on an HTML element or &lt;c-element&gt;, including inside nested templates. Component tags are not checked.</p><p><strong>Default severity:</strong> <code>error</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.invalid-attribute-value"><h2 id="citry.template.invalid-attribute-value" class="toc-heading"><code>citry.template.invalid-attribute-value</code></h2><p><strong>HTML attribute value the browser does not accept.</strong> An HTML attribute that accepts only certain keywords, such as draggable or type, has another value. The browser ignores it or falls back to a default, with no error.</p><p><strong>Messages:</strong></p><ul class="diagnostic-messages"><li class="diagnostic-message"><p><strong>default:</strong></p><div class="highlight"><pre><code>&#39;{value}&#39; is not a valid value for &#39;{attribute}&#39; on &lt;{element}&gt;. Valid values: {allowed}.</code></pre></div></li><li class="diagnostic-message"><p><strong>suggestion:</strong></p><div class="highlight"><pre><code>&#39;{value}&#39; is not a valid value for &#39;{attribute}&#39; on &lt;{element}&gt;. Did you mean &#39;{suggestion}&#39;? Valid values: {allowed}.</code></pre></div></li><li class="diagnostic-message"><p><strong>empty:</strong></p><div class="highlight"><pre><code>&#39;{attribute}&#39; on &lt;{element}&gt; needs a value. Valid values: {allowed}.</code></pre></div></li><li class="diagnostic-message"><p><strong>target:</strong></p><div class="highlight"><pre><code>&#39;{value}&#39; is not a valid value for &#39;{attribute}&#39; on &lt;{element}&gt;. A name that starts with &#39;_&#39; must be one of: {allowed}.</code></pre></div></li><li class="diagnostic-message"><p><strong>frame-name:</strong></p><div class="highlight"><pre><code>&#39;{value}&#39; is not a valid value for &#39;{attribute}&#39; on &lt;{element}&gt;. A frame name cannot start with &#39;_&#39;.</code></pre></div></li><li class="diagnostic-message"><p><strong>pragma:</strong></p><div class="highlight"><pre><code>&#39;{value}&#39; is not a pragma browsers act on in &#39;{attribute}&#39; on &lt;{element}&gt;. If it is an HTTP header, send it in the HTTP response instead. Valid values: {allowed}.</code></pre></div></li></ul><div class="diagnostic-example"><p><strong>Example: A misspelled keyword</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;div draggable=&#34;treu&#34;&gt;Drag me&lt;/div&gt;</code></pre></div></div><div class="diagnostic-example"><p><strong>Example: An input type the browser does not know</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;input type=&#34;datetime&#34; name=&#34;start&#34;&gt;</code></pre></div></div><p><strong>Fix:</strong> Use one of the valid values the message lists. If a script on the page reads its own values from the attribute, set rule_invalid_attribute_value to &#34;ignore&#34; for that component.</p><p><strong>When this appears:</strong> The value is not one of the keywords the HTML Standard lists for that attribute on that element. Letter case does not matter, except for list markers in type on &lt;ol&gt; and &lt;li&gt;. A Vue binding whose value is one JavaScript string, such as :dir=&#34;&#39;rtl&#39;&#34;, is checked too. Other bound values, component tags, &lt;c-element&gt;, custom elements, elements inside &lt;svg&gt; or &lt;math&gt;, and attributes that take a list of words, such as rel, are not checked.</p><p><strong>Default severity:</strong> <code>warning</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.js-data.unsupported-type"><h2 id="citry.js-data.unsupported-type" class="toc-heading"><code>citry.js-data.unsupported-type</code></h2><p><strong>JsData field is not a JSON type.</strong> A JsData field has a type that cannot be sent to the browser as JSON, such as a set or a date. Editor help treats the value as any.</p><p><strong>Message:</strong></p><div class="highlight"><pre><code>JsData field &#39;{name}&#39; is not a clean JSON value: {detail}. Browser tooling will treat its type as unknown.</code></pre></div><div class="diagnostic-example"><p><strong>Example: Unsupported set value</strong></p><div class="highlight"><pre><code class="language-citry">class Card(Component):
    class JsData:
        selected_ids: set[int]</code></pre></div></div><p><strong>Fix:</strong> Convert the value to JSON-friendly data in js_data(), such as a list, a string, or a dict of plain values, and change the JsData annotation to match.</p><p><strong>When this appears:</strong> A declared or inferred JsData field has a type that strict JSON cannot carry, such as bytes, a set, a callable, a date or time, or a whole class instance.</p><p><strong>Default severity:</strong> <code>warning</code>. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.js-data.public-name-collision"><h2 id="citry.js-data.public-name-collision" class="toc-heading"><code>citry.js-data.public-name-collision</code></h2><p><strong>JsData field conflicts with a public instance name.</strong> A JsData field has the same name as something already on the component instance in the browser, such as a prop, a method, or a name Vue reserves.</p><p><strong>Messages:</strong></p><ul class="diagnostic-messages"><li class="diagnostic-message"><p><strong>default:</strong></p><div class="highlight"><pre><code>JsData field &#39;{name}&#39; conflicts with a reserved or component-defined public instance name.</code></pre></div></li><li class="diagnostic-message"><p><strong>conditional:</strong></p><div class="highlight"><pre><code>JsData field &#39;{name}&#39; conflicts with a reserved or component-defined public instance name when supplied.</code></pre></div></li></ul><p><strong>Fix:</strong> Rename the JsData field, or rename the Vue Options entry it collides with.</p><p><strong>When this appears:</strong> A JsData field that Citry can see in the source uses a reserved browser name or the name of a Vue Options entry, such as a prop, method, or computed value.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.vue.unknown-variable"><h2 id="citry.vue.unknown-variable" class="toc-heading"><code>citry.vue.unknown-variable</code></h2><p><strong>Unknown Vue variable.</strong> A Vue expression reads a name the component does not send to the browser, often because of a typo. Vue shows nothing, or the expression fails in the browser.</p><p><strong>Messages:</strong></p><ul class="diagnostic-messages"><li class="diagnostic-message"><p><strong>default:</strong></p><div class="highlight"><pre><code>Vue variable &#39;{name}&#39; is not available in this component.</code></pre></div></li><li class="diagnostic-message"><p><strong>python:</strong></p><div class="highlight"><pre><code>Vue variable &#39;{name}&#39; is not available in this component. &#39;{name}&#39; is a Python variable here, which the browser never sees; pass its value with a c- attribute or loop with Vue&#39;s v-for.</code></pre></div></li></ul><div class="diagnostic-example"><p><strong>Example: Unknown name in a Vue expression</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;button :disabled=&#34;submitting1&#34;&gt;Save&lt;/button&gt;</code></pre></div></div><p><strong>Fix:</strong> Correct the name, or send the value from js_data(). If it is a Python variable, pass it with a c- attribute instead. Declare names that come from outside Citry in vue_variables, or change rule_unknown_vue_variable.</p><p><strong>When this appears:</strong> A name in a Vue expression is not a JsData or js_data() key, a v-for or slot alias around it, a Vue or Citry helper, a browser global, or a declared vue_variables entry.</p><p><strong>Default severity:</strong> <code>error</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.vue.python-variable"><h2 id="citry.vue.python-variable" class="toc-heading"><code>citry.vue.python-variable</code></h2><p><strong>Python variable read by a Vue expression.</strong> A Vue expression reads a Python c-for or c-fill variable. The browser never sees that variable, so the value is missing, or Vue shows a different browser value with the same name.</p><p><strong>Messages:</strong></p><ul class="diagnostic-messages"><li class="diagnostic-message"><p><strong>default:</strong></p><div class="highlight"><pre><code>Vue reads &#39;{name}&#39; from browser state, but &#39;{name}&#39; is a Python variable here. Pass its value with a c- attribute or loop with Vue&#39;s v-for instead.</code></pre></div></li><li class="diagnostic-message"><p><strong>attribute:</strong></p><div class="highlight"><pre><code>Vue reads &#39;{name}&#39; from browser state, but &#39;{name}&#39; is a Python variable here. Use c-{attribute}=&#34;{name}&#34; to pass the Python value.</code></pre></div></li><li class="diagnostic-message"><p><strong>browser:</strong></p><div class="highlight"><pre><code>Vue reads the component&#39;s browser value &#39;{name}&#39; here, not the Python loop or slot variable &#39;{name}&#39;. Pass the Python value with a c- attribute, or rename one of them.</code></pre></div></li><li class="diagnostic-message"><p><strong>browser-attribute:</strong></p><div class="highlight"><pre><code>Vue reads the component&#39;s browser value &#39;{name}&#39; here, not the Python loop or slot variable &#39;{name}&#39;. Use c-{attribute}=&#34;{name}&#34; for the Python value, or rename one of them.</code></pre></div></li></ul><div class="diagnostic-example"><p><strong>Example: Python loop variable in a Vue binding</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;li c-for=&#34;item in items&#34; :title=&#34;item&#34;&gt;&lt;/li&gt;</code></pre></div></div><p><strong>Fix:</strong> Pass the Python value with a c- attribute, such as c-title=&#34;item&#34; instead of :title=&#34;item&#34;, or loop with Vue&#39;s v-for. If a browser value has the same name, rename one of them.</p><p><strong>When this appears:</strong> A Vue expression inside a c-for loop or c-fill binding reads the Python variable, and no Vue v-for or slot alias of that name is around it. When Citry knows every name the component sends to the browser and the name is not among them, it reports citry.vue.unknown-variable instead, unless that rule is set to ignore.</p><p><strong>Default severity:</strong> <code>warning</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.component-js.unknown-variable"><h2 id="citry.component-js.unknown-variable" class="toc-heading"><code>citry.component-js.unknown-variable</code></h2><p><strong>Unknown component JavaScript variable.</strong> Code inside $component reads a name that is not declared there, often a callback value you forgot to destructure. It fails in the browser.</p><p><strong>Message:</strong></p><div class="highlight"><pre><code>Component JavaScript variable &#39;{name}&#39; is not defined.</code></pre></div><div class="diagnostic-example"><p><strong>Example: Undeclared name in a callback</strong></p><div class="highlight"><pre><code class="language-javascript">$component(({ component }) =&gt; {
  component.ready = settings.ready;
});</code></pre></div></div><p><strong>Fix:</strong> Declare or destructure the name, or read the value from the component instance. If a project script defines it as a global, declare it in component_js_globals, or change rule_unknown_component_js_variable.</p><p><strong>When this appears:</strong> A name inside a $component initializer is not declared in that code, destructured from the callback&#39;s argument, a JavaScript or browser global, or a declared component_js_globals entry.</p><p><strong>Default severity:</strong> <code>error</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.component-js.unknown-member"><h2 id="citry.component-js.unknown-member" class="toc-heading"><code>citry.component-js.unknown-member</code></h2><p><strong>Unknown component instance member.</strong> Component JavaScript reads this.&lt;name&gt; or component.&lt;name&gt;, and the component has no member with that name, often because of a typo. The value is undefined in the browser.</p><p><strong>Message:</strong></p><div class="highlight"><pre><code>Component instance member &#39;{name}&#39; is not defined by this component.</code></pre></div><div class="diagnostic-example"><p><strong>Example: Misspelled js_data() key in a callback</strong></p><div class="highlight"><pre><code class="language-javascript">$component(({ component }) =&gt; {
  console.log(component.missing_field);
});</code></pre></div></div><p><strong>Fix:</strong> Correct the name, or define it on the component. A plugin that adds a property to every component should give it a $ prefix, such as $api.</p><p><strong>When this appears:</strong> The name is not a js_data() key, prop, data() key, setup binding, method, computed value, or injection. Citry checks only when it can see every js_data() key and every Vue Options section in the source. It skips names that start with $ or _, bracket reads such as component[key], and code that uses mixins, extends, Object.assign, a class, or computed member names.</p><p><strong>Default severity:</strong> <code>error</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.browser.invalid-state-binding-target"><h2 id="citry.browser.invalid-state-binding-target" class="toc-heading"><code>citry.browser.invalid-state-binding-target</code></h2><p><strong>Invalid State binding target.</strong> A :c-* State binding is on an element that has no value to bind, such as a &lt;div&gt;, or an input type that cannot hold one, such as a file input.</p><div class="diagnostic-example"><p><strong>Example: Binding on a non-control element</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;head :c-query&gt;&lt;/head&gt;</code></pre></div></div><p><strong>Fix:</strong> Bind a form control that holds a value, such as &lt;input&gt;, &lt;select&gt;, or &lt;textarea&gt;. On a custom element, name its update event with .on:&lt;event&gt;. To react to an event on another element, use an @c-* binding instead.</p><p><strong>When this appears:</strong> The element or input type cannot hold a bound value, or does not support the binding&#39;s direction or update event.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>

<section class="diagnostic-reference" aria-labelledby="citry.format.embedded-interpolation-unsupported"><h2 id="citry.format.embedded-interpolation-unsupported" class="toc-heading"><code>citry.format.embedded-interpolation-unsupported</code></h2><p><strong>Embedded interpolation unsupported.</strong> A JavaScript or CSS region contains Citry interpolation, such as {{ title }}, so it was left unchanged.</p><div class="diagnostic-example"><p><strong>Example: Citry interpolation inside JavaScript</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;script&gt;
  const title = &#34;{{ title }}&#34;;
&lt;/script&gt;</code></pre></div></div><p><strong>Fix:</strong> Pass the value through js_data() or css_data() instead of interpolating it, or leave the region unformatted.</p><p><strong>When this appears:</strong> An embedded JavaScript or CSS region contains Citry interpolation, which an external formatter cannot handle safely.</p><p><strong>Default severity:</strong> <code>warning</code>. <strong>Reported by:</strong> <code>citry format</code>, <code>citry-lsp</code>, the Citry VS Code extension.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.format.provider-unavailable"><h2 id="citry.format.provider-unavailable" class="toc-heading"><code>citry.format.provider-unavailable</code></h2><p><strong>Embedded formatter unavailable.</strong> No JavaScript or CSS formatter answered, so that region was left unchanged.</p><p><strong>Fix:</strong> In VS Code, check that Prettier for VS Code is installed and enabled for the language, or disable it so Citry uses its own copy of Prettier.</p><p><strong>When this appears:</strong> Citry asks the editor to format embedded JavaScript or CSS, and no installed formatter returns an edit.</p><p><strong>Default severity:</strong> <code>warning</code>. <strong>Reported by:</strong> <code>citry format</code>, <code>citry-lsp</code>, the Citry VS Code extension.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.format.host-syntax"><h2 id="citry.format.host-syntax" class="toc-heading"><code>citry.format.host-syntax</code></h2><p><strong>Invalid Python host syntax.</strong> The Python file has a syntax error, so Citry could not find the component strings to format.</p><p><strong>Fix:</strong> Fix the Python syntax error, then format again.</p><p><strong>When this appears:</strong> A format command targets a Python file that is not valid Python.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry format</code>, <code>citry-lsp</code>, the Citry VS Code extension.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.format.ineligible"><h2 id="citry.format.ineligible" class="toc-heading"><code>citry.format.ineligible</code></h2><p><strong>Document is not eligible for formatting.</strong> The file or cursor position is not inside a Citry template, script, or style, so there is nothing to format.</p><p><strong>Fix:</strong> Place the cursor inside a template, js, or css string, or open the template file itself.</p><p><strong>When this appears:</strong> Citry cannot tell that the document or cursor position belongs to a template, js, or css string, or a standalone Citry template.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry format</code>, <code>citry-lsp</code>, the Citry VS Code extension.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.format.stale-document"><h2 id="citry.format.stale-document" class="toc-heading"><code>citry.format.stale-document</code></h2><p><strong>Document changed during formatting.</strong> The document changed while Citry was formatting it, so the result was discarded.</p><p><strong>Fix:</strong> Run the format command again.</p><p><strong>When this appears:</strong> The document changes after Citry prepares the edit and before the editor applies it.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry-lsp</code>, the Citry VS Code extension.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.format.cancelled"><h2 id="citry.format.cancelled" class="toc-heading"><code>citry.format.cancelled</code></h2><p><strong>Formatting cancelled.</strong> Formatting was cancelled before Citry applied it.</p><p><strong>Fix:</strong> Nothing to fix. Run the format command again if needed.</p><p><strong>When this appears:</strong> The editor or you cancel a format request before Citry applies its edits.</p><p><strong>Default severity:</strong> <code>information</code>. <strong>Reported by:</strong> the Citry VS Code extension.</p></section>
<h2 id="provider-owned-diagnostics" class="toc-heading">Codes from the type checkers</h2>
<section class="diagnostic-reference"><h3><code>citry.python.*</code></h3><p><strong>Reported by:</strong> ty. Python type errors in template expressions and c-* values, such as a value of the wrong type for a component input. They come from ty, the Python type checker Citry runs. The part after citry.python. is ty&#39;s rule name, and the message is ty&#39;s.</p></section>
<section class="diagnostic-reference"><h3><code>citry.typescript.*</code></h3><p><strong>Reported by:</strong> TypeScript. TypeScript errors in component JavaScript and Vue expressions, such as a wrong argument type, an unknown member, or a wrong number of arguments. The part after citry.typescript. is TypeScript&#39;s error number, such as ts2322, and the message is TypeScript&#39;s. When one of Citry&#39;s own diagnostics already reports the same mistake, Citry shows only its own.</p></section>
