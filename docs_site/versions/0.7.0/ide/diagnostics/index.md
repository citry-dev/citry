# Diagnostic reference

Every error and warning Citry reports has a code, such as
`citry.template.unknown-variable`. The editor shows it next to the message,
and `citry check` prints it with each finding. Find the code below to see what
went wrong and how to fix it.

The code always names the same mistake in every tool: the editor,
`citry check`, `citry format`, and the template parser. The message can add details,
such as the name you misspelled.

Some rules can be made stricter or turned off. Those entries say "Your
application can change this severity". For the template lint rules, see
[Template linting](/v/0.7.0/ide/template-linting/#change-how-strict-a-rule-is).

Codes that start with `citry.python.` or `citry.typescript.` come from the
Python and TypeScript type checkers. They are listed at the end of this page.

<div class="diagnostic-catalog">
<section class="diagnostic-reference" aria-labelledby="citry.parse.syntax"><h2 id="citry.parse.syntax" class="toc-heading"><code>citry.parse.syntax</code></h2><p><strong>Invalid template syntax.</strong> The template has a syntax mistake, such as an unclosed element or an unfinished expression. Citry cannot read the template, so it does not render.</p><div class="diagnostic-example"><p><strong>Example: Unclosed element</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;section&gt;
  &lt;p&gt;Hello&lt;/p&gt;</code></pre></div></div><p><strong>Fix:</strong> Correct the template at the reported position. The message says what the parser expected there.</p><p><strong>When this appears:</strong> The parser finds malformed markup, an incomplete expression, or another syntax error. Only the first syntax error in a template is reported.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> template parser APIs, <code>citry format</code>, <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.parse.value"><h2 id="citry.parse.value" class="toc-heading"><code>citry.parse.value</code></h2><p><strong>Invalid template value.</strong> Citry was given a value it cannot parse as a template. This is usually not a mistake in your template text.</p><p><strong>Fix:</strong> If an extension adds its own template syntax, update it or report the message to its authors. Otherwise, report the message as a Citry bug.</p><p><strong>When this appears:</strong> A parser API receives a value it cannot turn into template source, for example when an extension that adds its own template syntax reports positions that do not fit the template.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> template parser APIs, <code>citry format</code>, <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.parse.too-deep"><h2 id="citry.parse.too-deep" class="toc-heading"><code>citry.parse.too-deep</code></h2><p><strong>Template nested too deeply.</strong> The template nests tags deeper than Citry allows, so it does not render.</p><div class="diagnostic-example"><p><strong>Example: Tags of any kind past the total limit</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;div&gt;
  &lt;div&gt;
    &lt;!-- ... 510 more nested &lt;div&gt; tags ... --&gt;
    &lt;p&gt;Too deep&lt;/p&gt;
  &lt;/div&gt;
&lt;/div&gt;</code></pre></div></div><div class="diagnostic-example"><p><strong>Example: Logic tags past the logic limit</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;c-if cond=&#34;a&#34;&gt;
  &lt;c-for each=&#34;item in items&#34;&gt;
    &lt;!-- ... 254 more nested logic tags ... --&gt;
    &lt;c-if cond=&#34;b&#34;&gt;Too deep&lt;/c-if&gt;
  &lt;/c-for&gt;
&lt;/c-if&gt;</code></pre></div></div><p><strong>Fix:</strong> Move the inner part into its own component&#39;s template, which starts counting from zero. Markup passed to a component between its tags still counts toward the template that writes it.</p><p><strong>When this appears:</strong> A tag would sit more than 512 levels deep, or more than 256 Citry logic levels deep: every c- tag except &lt;c-raw&gt;, and each c-if=, c-elif=, c-else, c-for= or c-empty attribute. A template inside an attribute counts from the depth of the tag that holds it.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> template parser APIs, <code>citry format</code>, <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.parse.configuration"><h2 id="citry.parse.configuration" class="toc-heading"><code>citry.parse.configuration</code></h2><p><strong>Template parser setup failed.</strong> Citry could not set up the template parser for your application, so it cannot check this template.</p><p><strong>Fix:</strong> Read the message for the rule that failed, and fix the application or extension that defines it.</p><p><strong>When this appears:</strong> The tag rules that your application or its extensions add to the parser cannot be built or applied.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.unknown-variable"><h2 id="citry.template.unknown-variable" class="toc-heading"><code>citry.template.unknown-variable</code></h2><p><strong>Unknown template variable.</strong> A template reads a variable that nothing provides, often because of a typo. Rendering then fails with a KeyError.</p><p><strong>Messages:</strong></p><ul class="diagnostic-messages"><li class="diagnostic-message"><p><strong>Closed template data:</strong></p><div class="highlight"><pre><code>Template variable &#39;{name}&#39; is not available in this template.</code></pre></div></li><li class="diagnostic-message"><p><strong>Template data allows extra names:</strong></p><div class="highlight"><pre><code>Template variable &#39;{name}&#39; is not declared. It may be supplied dynamically.</code></pre></div></li><li class="diagnostic-message"><p><strong>Template data could not be inspected:</strong></p><div class="highlight"><pre><code>Template variable &#39;{name}&#39; is not declared. Citry could not determine whether it is supplied dynamically.</code></pre></div></li></ul><div class="diagnostic-example"><p><strong>Example: Unknown name in an interpolation</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;p&gt;{{ missing_name }}&lt;/p&gt;</code></pre></div></div><div class="diagnostic-example"><p><strong>Example: Unknown name in a dynamic attribute</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;div c-title=&#34;missing_name&#34;&gt;&lt;/div&gt;</code></pre></div></div><p><strong>Fix:</strong> Correct the name, or add it to the data that template_data() returns. If template_data() builds its result in a way Citry cannot read, such as by calling a helper function, list every key it returns in Lint.template_data_keys. If another integration provides the name, declare it in template_variables, or change rule_unknown_template_variable.</p><p><strong>When this appears:</strong> A name in {{ ... }} or in a c-* attribute is not in the component&#39;s template data, a c-for or c-fill binding around it, template_globals, or the declared template_variables. In a template that several components share, every one of them must provide the name.</p><p><strong>Default severity:</strong> <code>error</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.undeclared-template-data-key"><h2 id="citry.template.undeclared-template-data-key" class="toc-heading"><code>citry.template.undeclared-template-data-key</code></h2><p><strong>Key missing from template_data_keys.</strong> A component&#39;s template_data() returns a key that its Lint.template_data_keys does not list, so the list no longer names every key the method returns.</p><p><strong>Message:</strong></p><div class="highlight"><pre><code>template_data() returns &#39;{name}&#39;, but Lint.template_data_keys does not list it. Add &#39;{name}&#39; to the list so it names every key the method returns.</code></pre></div><div class="diagnostic-example"><p><strong>Example: A key the list leaves out</strong></p><div class="highlight"><pre><code class="language-citry">class Card(Component):
    class Lint:
        template_data_keys = (&#34;title&#34;,)

    def template_data(self, kwargs, slots):
        data = build_card(kwargs)
        data[&#34;badge&#34;] = &#34;new&#34;
        return data</code></pre></div></div><p><strong>Fix:</strong> Add the key to Lint.template_data_keys, or stop returning it.</p><p><strong>When this appears:</strong> A component declares Lint.template_data_keys, and its template_data() writes a key as a literal, such as {&#34;title&#34;: ...} or data[&#34;title&#34;] = ..., that the list leaves out.</p><p><strong>Default severity:</strong> <code>warning</code>. <strong>Reported by:</strong> <code>citry check</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.unknown-component"><h2 id="citry.template.unknown-component" class="toc-heading"><code>citry.template.unknown-component</code></h2><p><strong>Unknown component.</strong> A component tag names a component that your application does not register, often because of a typo. The template fails to render.</p><p><strong>Message:</strong></p><div class="highlight"><pre><code>Component &lt;{tag}&gt; is not registered.</code></pre></div><div class="diagnostic-example"><p><strong>Example: Unregistered component tag</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;c-missing-card /&gt;</code></pre></div></div><p><strong>Fix:</strong> Correct the tag name, or register the component with the application that Citry loaded.</p><p><strong>When this appears:</strong> A &lt;c-*&gt; tag names no component in the selected application or library, counting built-in names and aliases.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.marker-name-invalid"><h2 id="citry.template.marker-name-invalid" class="toc-heading"><code>citry.template.marker-name-invalid</code></h2><p><strong>Invalid &lt;c-mark&gt; tag.</strong> A &lt;c-mark&gt; tag, which marks part of a component that an event handler can replace, has no usable name, an extra attribute, or content it does not accept.</p><p><strong>Messages:</strong></p><ul class="diagnostic-messages"><li class="diagnostic-message"><p><strong>dynamic:</strong></p><div class="highlight"><pre><code>Marker name must be a static literal.</code></pre></div></li><li class="diagnostic-message"><p><strong>invalid:</strong></p><div class="highlight"><pre><code>Marker name must match [A-Za-z][A-Za-z0-9_-]*.</code></pre></div></li><li class="diagnostic-message"><p><strong>missing:</strong></p><div class="highlight"><pre><code>Marker requires a literal name attribute.</code></pre></div></li><li class="diagnostic-message"><p><strong>extra:</strong></p><div class="highlight"><pre><code>Marker accepts only its name attribute.</code></pre></div></li><li class="diagnostic-message"><p><strong>named_fill:</strong></p><div class="highlight"><pre><code>Marker accepts only its default slot.</code></pre></div></li></ul><p><strong>Fix:</strong> Give the marker one literal name that starts with a letter and contains only letters, digits, _ or -. Remove other attributes and named fills.</p><p><strong>When this appears:</strong> A &lt;c-mark&gt; tag has no name attribute, a dynamic or invalid name, any other attribute, or a named fill.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.alpine-attribute"><h2 id="citry.template.alpine-attribute" class="toc-heading"><code>citry.template.alpine-attribute</code></h2><p><strong>Alpine attribute on an HTML element.</strong> An HTML element still has an Alpine x-* attribute, such as x-data or x-on:click. Citry uses Vue, so nothing reads it and it does nothing.</p><p><strong>Message:</strong></p><div class="highlight"><pre><code>&#39;{name}&#39; is an Alpine attribute. Citry uses Vue, so nothing reads it. Replace it with its Vue form, or set rule_alpine_attribute to &#39;ignore&#39; if a library on the page reads &#39;{name}&#39;.</code></pre></div><div class="diagnostic-example"><p><strong>Example: Alpine state on an element</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;div x-data=&#34;{ open: false }&#34;&gt;
  &lt;button x-on:click=&#34;open = !open&#34;&gt;Menu&lt;/button&gt;
&lt;/div&gt;</code></pre></div></div><p><strong>Fix:</strong> Move the state into js_data() or $component, and write the listener in its Vue form, such as @click. If another library on the page reads x-* attributes, set rule_alpine_attribute to &#34;ignore&#34;.</p><p><strong>When this appears:</strong> An Alpine directive name, such as x-data, x-on:click, or x-intersect, sits on an HTML element or &lt;c-element&gt;, including inside nested templates. Other x-* names, such as x-webkit-airplay, are ordinary HTML. Component tags are not checked, because an x-* attribute there is a Python keyword argument. x-cloak is reported as citry.template.alpine-cloak.</p><p><strong>Default severity:</strong> <code>warning</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.alpine-cloak"><h2 id="citry.template.alpine-cloak" class="toc-heading"><code>citry.template.alpine-cloak</code></h2><p><strong>x-cloak hides an element for good.</strong> An HTML element still has x-cloak. Nothing removes it, so a [x-cloak] CSS rule hides the element for good.</p><p><strong>Message:</strong></p><div class="highlight"><pre><code>Nothing in Citry removes &#39;x-cloak&#39;, so a &#39;[x-cloak]&#39; CSS rule keeps this element hidden. Delete &#39;x-cloak&#39; and its &#39;[x-cloak]&#39; rule; the server-rendered HTML already shows the content.</code></pre></div><div class="diagnostic-example"><p><strong>Example: Leftover x-cloak</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;div x-cloak&gt;{{ message }}&lt;/div&gt;</code></pre></div></div><p><strong>Fix:</strong> Delete x-cloak and its [x-cloak] CSS rule. The HTML from the server already shows the content.</p><p><strong>When this appears:</strong> x-cloak, in any letter case, sits on an HTML element or &lt;c-element&gt;, including inside nested templates. Component tags are not checked.</p><p><strong>Default severity:</strong> <code>error</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.invalid-attribute-value"><h2 id="citry.template.invalid-attribute-value" class="toc-heading"><code>citry.template.invalid-attribute-value</code></h2><p><strong>HTML attribute value the browser does not accept.</strong> An HTML attribute that accepts only certain keywords, such as draggable or type, has another value, or a boolean attribute such as disabled has a value other than empty or its own name, which still turns it on. The browser raises no error either way.</p><p><strong>Messages:</strong></p><ul class="diagnostic-messages"><li class="diagnostic-message"><p><strong>default:</strong></p><div class="highlight"><pre><code>&#39;{value}&#39; is not a valid value for &#39;{attribute}&#39; on &lt;{element}&gt;. Valid values: {allowed}.</code></pre></div></li><li class="diagnostic-message"><p><strong>suggestion:</strong></p><div class="highlight"><pre><code>&#39;{value}&#39; is not a valid value for &#39;{attribute}&#39; on &lt;{element}&gt;. Did you mean &#39;{suggestion}&#39;? Valid values: {allowed}.</code></pre></div></li><li class="diagnostic-message"><p><strong>empty:</strong></p><div class="highlight"><pre><code>&#39;{attribute}&#39; on &lt;{element}&gt; needs a value. Valid values: {allowed}.</code></pre></div></li><li class="diagnostic-message"><p><strong>target:</strong></p><div class="highlight"><pre><code>&#39;{value}&#39; is not a valid value for &#39;{attribute}&#39; on &lt;{element}&gt;. A name that starts with &#39;_&#39; must be one of: {allowed}.</code></pre></div></li><li class="diagnostic-message"><p><strong>frame-name:</strong></p><div class="highlight"><pre><code>&#39;{value}&#39; is not a valid value for &#39;{attribute}&#39; on &lt;{element}&gt;. A frame name cannot start with &#39;_&#39;.</code></pre></div></li><li class="diagnostic-message"><p><strong>pragma:</strong></p><div class="highlight"><pre><code>&#39;{value}&#39; is not a pragma browsers act on in &#39;{attribute}&#39; on &lt;{element}&gt;. If it is an HTTP header, send it in the HTTP response instead. Valid values: {allowed}.</code></pre></div></li><li class="diagnostic-message"><p><strong>boolean:</strong></p><div class="highlight"><pre><code>&#39;{attribute}&#39; on &lt;{element}&gt; is on whenever it is present, so &#39;{value}&#39; still turns it on. Write it with no value to turn it on, and leave it out to turn it off.</code></pre></div></li><li class="diagnostic-message"><p><strong>boolean-binding:</strong></p><div class="highlight"><pre><code>&#39;{attribute}&#39; on &lt;{element}&gt; is on whenever it is present, so the string &#39;{value}&#39; still turns it on. Bind a JavaScript boolean instead, such as :{attribute}=&#34;false&#34;.</code></pre></div></li></ul><div class="diagnostic-example"><p><strong>Example: A misspelled keyword</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;div draggable=&#34;treu&#34;&gt;Drag me&lt;/div&gt;</code></pre></div></div><div class="diagnostic-example"><p><strong>Example: An input type the browser does not know</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;input type=&#34;datetime&#34; name=&#34;start&#34;&gt;</code></pre></div></div><div class="diagnostic-example"><p><strong>Example: A boolean attribute set to false</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;button disabled=&#34;false&#34;&gt;Search&lt;/button&gt;</code></pre></div></div><p><strong>Fix:</strong> Use one of the valid values the message lists. For a boolean attribute, write it with no value, leave it out, or bind a JavaScript boolean such as :disabled=&#34;saving&#34;. If a script on the page reads its own values from the attribute, set rule_invalid_attribute_value to &#34;ignore&#34; for that component.</p><p><strong>When this appears:</strong> The value is not one of the keywords the HTML Standard lists for that attribute on that element. A boolean attribute, such as disabled or required, is on whenever it is present, so any value other than the empty string or the attribute&#39;s own name is reported, including &#34;false&#34; and &#34;true&#34;. Letter case does not matter, except for list markers in type on &lt;ol&gt; and &lt;li&gt;. A Vue binding whose value is one JavaScript string, such as :dir=&#34;&#39;rtl&#39;&#34;, is checked too. Other bound values, component tags, &lt;c-element&gt;, custom elements, elements inside &lt;svg&gt; or &lt;math&gt;, and attributes that take a list of words, such as rel, are not checked. citry check --static and an editor that has not loaded your application report it as a warning unless the component&#39;s own Lint class sets the rule as a plain string, because they cannot read your LintSettings.</p><p><strong>Default severity:</strong> <code>error</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.misspelled-directive"><h2 id="citry.template.misspelled-directive" class="toc-heading"><code>citry.template.misspelled-directive</code></h2><p><strong>Misspelled Citry directive.</strong> A c-* attribute on an HTML element looks like a Citry directive, such as c-iff for c-if, but is not one, so Citry renders it as an ordinary attribute and the directive never runs. Or a v-* attribute looks like a Vue directive, such as v-iff for v-if, so Vue looks for a custom directive of that name and the page fails.</p><p><strong>Messages:</strong></p><ul class="diagnostic-messages"><li class="diagnostic-message"><p><strong>default:</strong></p><div class="highlight"><pre><code>&#39;{name}&#39; is not a Citry directive, so it renders an HTML attribute named &#39;{attribute}&#39;. Did you mean &#39;{suggestion}&#39;?</code></pre></div></li><li class="diagnostic-message"><p><strong>vue:</strong></p><div class="highlight"><pre><code>&#39;{name}&#39; is not a Citry directive, so it renders an HTML attribute named &#39;{attribute}&#39;. For Vue&#39;s directive, write &#39;{suggestion}&#39;.</code></pre></div></li><li class="diagnostic-message"><p><strong>vue-directive:</strong></p><div class="highlight"><pre><code>&#39;{name}&#39; is not a Vue directive, so Vue looks for a custom directive of that name and the page fails in the browser. Did you mean &#39;{suggestion}&#39;?</code></pre></div></li></ul><div class="diagnostic-example"><p><strong>Example: A typo in c-if</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;div c-iff=&#34;show&#34;&gt;Details&lt;/div&gt;</code></pre></div></div><div class="diagnostic-example"><p><strong>Example: A directive name from Vue</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;input c-model=&#34;query&#34;&gt;</code></pre></div></div><div class="diagnostic-example"><p><strong>Example: A typo in v-if</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;p v-iff=&#34;open&#34;&gt;Details&lt;/p&gt;</code></pre></div></div><p><strong>Fix:</strong> Use the directive the message names. For a custom directive, register it in the directives option of $component({...}). If the attribute really is meant for the browser, pass it through c-bind, such as c-bind=&#34;{&#39;show&#39;: value}&#34;. For a directive a plugin registers, set rule_misspelled_directive to &#34;ignore&#34; for that component.</p><p><strong>When this appears:</strong> The part after c- is not an HTML attribute that the element accepts, and it looks like a directive: if, elif, else, for, empty, or bind with two neighboring letters swapped, one letter typed twice, or one letter left out, such as c-fro, c-iff, or c-ele; one of those in other letter case, such as c-If; a spelled-out c-elif, such as c-else-if; c-show for c-if or c-model for v-model; or c-key or c-ignore without the #. A different letter, or an extra letter that is not a double, is not a typo, because it usually makes an ordinary word such as c-kind or c-form; neither are c-or, c-bid, c-bin, or a one-letter name. On a custom element, which can define its own attributes, the c-show, c-model, c-key, and c-ignore names are not reported. Only HTML elements, custom elements, and &lt;c-element&gt; are checked, not component tags or elements inside &lt;svg&gt; or &lt;math&gt;. A v-* name is reported on any element outside &lt;svg&gt;, &lt;math&gt;, and v-pre content, component tags included, when it is not a Vue directive and it is a typing slip (two neighboring letters swapped, one letter typed twice, or one letter left out) away from one, such as v-iff, v-shwo, or v-IFF, or is a spelled-out v-else-if, such as v-elif or v-elseif. A custom directive whose name is one slip from a Vue directive is not reported when every component that renders the template registers it in the directives option of $component({...}), under the name as written, its camelCase form, or that form with a capital first letter, such as directives: { iff: {...} } for v-iff or { myDir: {...} } for v-my-dir. Only citry check without --static and an editor that has loaded your application skip it. It is still reported when Citry cannot read that option, and for a directive that a plugin registers with Citry.vue.use(plugin), which no check can see. citry check --static and an editor that has not loaded your application report it too, with the severity the component&#39;s own Lint class sets as a plain string.</p><p><strong>Default severity:</strong> <code>error</code>. Your application can change this severity. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.template.misspelled-attribute"><h2 id="citry.template.misspelled-attribute" class="toc-heading"><code>citry.template.misspelled-attribute</code></h2><p><strong>Misspelled HTML attribute.</strong> An attribute on an HTML element looks like a typo of an attribute that element accepts, such as titel for title. The browser keeps it as an unknown attribute and ignores it, with no error.</p><p><strong>Message:</strong></p><div class="highlight"><pre><code>&#39;{name}&#39; is not an attribute of &lt;{element}&gt;, so the browser ignores it. Did you mean &#39;{suggestion}&#39;?</code></pre></div><div class="diagnostic-example"><p><strong>Example: A typo in title</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;div titel=&#34;Board&#34;&gt;...&lt;/div&gt;</code></pre></div></div><div class="diagnostic-example"><p><strong>Example: A typo in a Vue binding</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;img :scr=&#34;avatarUrl&#34;&gt;</code></pre></div></div><p><strong>Fix:</strong> Use the attribute the message names. If a script on the page really reads an attribute with this name, write it as data-&lt;name&gt;, or set rule_misspelled_attribute to &#34;ignore&#34; for that component.</p><p><strong>When this appears:</strong> The attribute is not one the HTML Standard lists for that element or for every element, and it is one typing slip from one that is: two neighboring letters swapped, one letter typed twice, or one letter left out, such as titel, clas, or herf. A binding such as :titel, v-bind:titel, or c-titel is checked by the attribute it sets. Letter case does not matter. Names with a hyphen or a colon, such as data-*, aria-*, or hx-*, bindings with a modifier such as .prop, component tags, custom elements, &lt;c-element&gt;, bindings on Vue&#39;s &lt;slot&gt;, and elements inside &lt;svg&gt; or &lt;math&gt; are not checked. <section class="diagnostic-reference" aria-labelledby="citry.template.csp-incompatible"><h2 id="citry.template.csp-incompatible" class="toc-heading"><code>citry.template.csp-incompatible</code></h2><p><strong>Breaks a strict Content Security Policy.</strong> The template writes something that a strict Content Security Policy blocks in the browser: an inline &lt;script&gt; or &lt;style&gt; element, an inline event attribute such as onclick, or a javascript: URL. Your application can turn it on. <strong>Reported by:</strong> <code>citry check</code>, <code>citry-lsp</code>.</p></section>

<section class="diagnostic-reference" aria-labelledby="citry.format.embedded-suppressed"><h2 id="citry.format.embedded-suppressed" class="toc-heading"><code>citry.format.embedded-suppressed</code></h2><p><strong>Embedded formatting suppressed.</strong> A fmt: off or fmt: skip comment kept a JavaScript or CSS region unformatted, as requested.</p><p><strong>Fix:</strong> Nothing to fix. Remove the directive if you want the region formatted.</p><p><strong>When this appears:</strong> A fmt: off or fmt: skip directive covers an embedded JavaScript or CSS region.</p><p><strong>Default severity:</strong> <code>information</code>. <strong>Reported by:</strong> <code>citry format</code>, <code>citry-lsp</code>, the Citry VS Code extension.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.format.embedded-language-unsupported"><h2 id="citry.format.embedded-language-unsupported" class="toc-heading"><code>citry.format.embedded-language-unsupported</code></h2><p><strong>Embedded language unsupported.</strong> A &lt;script&gt; or &lt;style&gt; region declares a language Citry has no formatter for, so it was left unchanged.</p><p><strong>Fix:</strong> Nothing to fix. Format that region with its own tools.</p><p><strong>When this appears:</strong> An embedded script or style region declares a language that no Citry formatter handles.</p><p><strong>Default severity:</strong> <code>warning</code>. <strong>Reported by:</strong> <code>citry format</code>, <code>citry-lsp</code>, the Citry VS Code extension.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.format.embedded-interpolation-unsupported"><h2 id="citry.format.embedded-interpolation-unsupported" class="toc-heading"><code>citry.format.embedded-interpolation-unsupported</code></h2><p><strong>Embedded interpolation unsupported.</strong> A JavaScript or CSS region contains Citry interpolation, such as {{ title }}, so it was left unchanged.</p><div class="diagnostic-example"><p><strong>Example: Citry interpolation inside JavaScript</strong></p><div class="highlight"><pre><code class="language-citry-html">&lt;script&gt;
  const title = &#34;{{ title }}&#34;;
&lt;/script&gt;</code></pre></div></div><p><strong>Fix:</strong> Pass the value through js_data() or css_data() instead of interpolating it, or leave the region unformatted.</p><p><strong>When this appears:</strong> An embedded JavaScript or CSS region contains Citry interpolation, which an external formatter cannot handle safely.</p><p><strong>Default severity:</strong> <code>warning</code>. <strong>Reported by:</strong> <code>citry format</code>, <code>citry-lsp</code>, the Citry VS Code extension.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.format.provider-unavailable"><h2 id="citry.format.provider-unavailable" class="toc-heading"><code>citry.format.provider-unavailable</code></h2><p><strong>Embedded formatter unavailable.</strong> No JavaScript or CSS formatter answered, so that region was left unchanged.</p><p><strong>Fix:</strong> In VS Code, check that Prettier for VS Code is installed and enabled for the language, or disable it so Citry uses its own copy of Prettier.</p><p><strong>When this appears:</strong> Citry asks the editor to format embedded JavaScript or CSS, and no installed formatter returns an edit.</p><p><strong>Default severity:</strong> <code>warning</code>. <strong>Reported by:</strong> <code>citry format</code>, <code>citry-lsp</code>, the Citry VS Code extension.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.format.host-syntax"><h2 id="citry.format.host-syntax" class="toc-heading"><code>citry.format.host-syntax</code></h2><p><strong>Invalid Python host syntax.</strong> The Python file has a syntax error, so Citry could not find the component strings to format.</p><p><strong>Fix:</strong> Fix the Python syntax error, then format again.</p><p><strong>When this appears:</strong> A format command targets a Python file that is not valid Python.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry format</code>, <code>citry-lsp</code>, the Citry VS Code extension.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.format.ineligible"><h2 id="citry.format.ineligible" class="toc-heading"><code>citry.format.ineligible</code></h2><p><strong>Document is not eligible for formatting.</strong> The file or cursor position is not inside a Citry template, script, or style, so there is nothing to format.</p><p><strong>Fix:</strong> Place the cursor inside a template, js, or css string, or open the template file itself.</p><p><strong>When this appears:</strong> Citry cannot tell that the document or cursor position belongs to a template, js, or css string, or a standalone Citry template.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry format</code>, <code>citry-lsp</code>, the Citry VS Code extension.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.format.stale-document"><h2 id="citry.format.stale-document" class="toc-heading"><code>citry.format.stale-document</code></h2><p><strong>Document changed during formatting.</strong> The document changed while Citry was formatting it, so the result was discarded.</p><p><strong>Fix:</strong> Run the format command again.</p><p><strong>When this appears:</strong> The document changes after Citry prepares the edit and before the editor applies it.</p><p><strong>Default severity:</strong> <code>error</code>. <strong>Reported by:</strong> <code>citry-lsp</code>, the Citry VS Code extension.</p></section>
<section class="diagnostic-reference" aria-labelledby="citry.format.cancelled"><h2 id="citry.format.cancelled" class="toc-heading"><code>citry.format.cancelled</code></h2><p><strong>Formatting cancelled.</strong> Formatting was cancelled before Citry applied it.</p><p><strong>Fix:</strong> Nothing to fix. Run the format command again if needed.</p><p><strong>When this appears:</strong> The editor or you cancel a format request before Citry applies its edits.</p><p><strong>Default severity:</strong> <code>information</code>. <strong>Reported by:</strong> the Citry VS Code extension.</p></section>
<h2 id="provider-owned-diagnostics" class="toc-heading">Codes from the type checkers</h2>
<section class="diagnostic-reference"><h3><code>citry.python.*</code></h3><p><strong>Reported by:</strong> ty. Python type errors in template expressions and c-* values, such as a value of the wrong type for a component input. They come from ty, the Python type checker Citry runs. The part after citry.python. is ty&#39;s rule name, and the message is ty&#39;s.</p></section>
<section class="diagnostic-reference"><h3><code>citry.typescript.*</code></h3><p><strong>Reported by:</strong> TypeScript. TypeScript errors in component JavaScript and Vue expressions, such as a wrong argument type, an unknown member, or a wrong number of arguments. The part after citry.typescript. is TypeScript&#39;s error number, such as ts2322, and the message is TypeScript&#39;s. When one of Citry&#39;s own diagnostics already reports the same mistake, Citry shows only its own.</p></section>
