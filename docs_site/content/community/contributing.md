# Contributing

You want to help Citry. Bug reports, fixes, ideas, and answered questions
all make the project better, and help of any size is welcome. Pick the
section that matches what you want to do.

## Report a bug { #found-a-bug }

Open
[an issue]({{ repo_url }}/issues/new/choose){: target="_blank" rel="noopener"}
that describes what went wrong. The more detail you give, the faster
someone can track it down. [Getting help](/community/help/#report-a-bug)
lists what to include.

## Send a fix { #got-a-fix }

Found a bug or a typo and know how to fix it? Open a
[pull request]({{ repo_url }}/pulls){: target="_blank" rel="noopener"}.
[Make a change](/community/development/#making-a-change) lists what a good
pull request includes, and we will help you get it merged.

## Suggest an idea { #have-an-idea }

- To talk an idea through first, start a
  [discussion]({{ repo_url }}/discussions){: target="_blank" rel="noopener"}.
- When you have a concrete proposal, open a
  [feature request]({{ repo_url }}/issues/new/choose){: target="_blank" rel="noopener"}.

Describe the problem before the solution. It helps a lot.

## Answer questions { #help-others }

You can help just by answering questions and sharing what you have worked
out:

- [Discussions]({{ repo_url }}/discussions){: target="_blank" rel="noopener"}
  hold questions, ideas, and general conversation.
- [Issues]({{ repo_issues_url }}){: target="_blank" rel="noopener"} hold bug
  reports and feature requests, where an extra pair of eyes often unblocks
  someone.

## Write code { #get-coding }

Citry is still young and there is a lot to build.

1. Find something to work on in the
   [open issues]({{ repo_issues_url }}){: target="_blank" rel="noopener"}.
   Issues labeled
   [good first issue]({{ repo_issues_url }}?q=is%3Aopen+is%3Aissue+label%3A%22good+first+issue%22){: target="_blank" rel="noopener"}
   are a friendly place to start.
2. [Set up your machine](/community/development/#getting-set-up).
3. Make your change, add or update tests, and
   [run the checks](/community/development/#running-the-checks).
4. Open a pull request.

A short version of this setup is in
[CONTRIBUTING.md]({{ repo_url }}/blob/{{ repo_edit_branch }}/CONTRIBUTING.md){: target="_blank" rel="noopener"}
in the repository. For how the codebase fits together (the Rust crates, the
language bindings, and how releases work), see
[docs/codebase.md]({{ repo_url }}/blob/{{ repo_edit_branch }}/docs/codebase.md){: target="_blank" rel="noopener"}.

## Sponsor the project { #support-the-project }

Citry is maintained in the open. To help keep it going,
[sponsor the project on GitHub]({{ repo_sponsors_url }}){: target="_blank" rel="noopener"}.
Every bit helps.

## Code of conduct

By taking part in the project you agree to follow the
