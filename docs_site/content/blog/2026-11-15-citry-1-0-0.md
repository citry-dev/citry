Citry 1.0.0 is out. It is the first stable release of Citry, the fully
typed frontend framework for Python.

Install it, or upgrade, with:

```console
python -m pip install -U "citry>=1.0.0,<2"
```

The language server `citry-lsp`, the VS Code extension, and
`pygments-citry` reach 1.0.0 at the same time.

## What "stable" means

From now on, an upgrade within 1.x keeps your code working. In short:

- **Patch releases** (1.0.1) fix bugs.
- **Minor releases** (1.1.0) add features. A deprecated feature keeps
  working, with a warning, until 2.0.0.
- **Only 2.0.0** may remove or break what 1.x documents.
- **During a rolling deploy** between two 1.x releases, an open page may
  reload once, but does not show an error.

The [Versioning and support](/about/versioning/) page has the exact
rules: what each kind of release may change, what counts as a breaking
change, and how to pin Citry.

## What the promise covers

The promise covers what the docs teach: the public Python names, the
template syntax, settings and extension hooks, the `citry` command line,
the browser JavaScript API, and the `citry-events/1` protocol that server
events use. See
[What the promise covers](/about/versioning/#what-is-covered) for the
full list.

A few features work and are tested, but their design is not settled yet,
so they are marked experimental and may change in a minor release. They
include component previews, the template analysis API behind
`citry check`, and running event calls from your own server code with
`EventsDispatcher`. They are listed under
[Experimental features](/about/versioning/#experimental).

The [UI library](/ui-library/) is not part of 1.0.0. citry-ui stays on
0.x as an alpha, so pin one minor release, such as
`"citry-ui>=0.6.0,<0.7"`.

## Upgrade to 1.0.0

Citry 0.9.0 made the last planned breaking changes, so the upgrade is
small. Upgrade to 0.9.x first and follow its upgrade notes, fix any
`CitryDeprecationWarning`, then upgrade to 1.0.0.

One change needs attention: signed State tokens, the State Citry keeps
in the page, now expire after 24 hours. A page left open longer reloads
once on its next event call. You can set a longer lifetime per component.

[Upgrade to Citry 1.0.0](/guides/upgrading-to-1-0-0/) walks through
every step, and the
[changelog](https://github.com/citry-dev/citry/blob/citry@1.0.0/CHANGELOG.md){: target="\_blank" rel="noopener"}
lists every change.

## Which versions get fixes

Bug and security fixes go to the newest 1.x minor release, so staying
up to date within 1.x is how you get them. When 2.0.0 comes out, the
last 1.x minor release gets security fixes for 12 months, and 0.x
releases get no more fixes from today.

## What comes next

Work continues in 1.x minor releases, starting with more settings for
`citry check` rules in 1.1.0. The
[Roadmap](https://github.com/citry-dev/citry/issues/79){: target="\_blank" rel="noopener"}
tracks what is planned. Tell me there, or on
[Discord](https://discord.gg/NaQ8QPyHtD){: target="\_blank" rel="noopener"},
what you need most.
