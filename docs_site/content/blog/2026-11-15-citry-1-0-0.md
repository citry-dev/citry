Citry 1.0.0 is out. It is the first stable release of Citry, the fully
typed frontend framework for Python.

Install it, or upgrade, with:

```console
python -m pip install -U "citry>=1.0.0,<2"
```

The language server `citry-lsp`, the VS Code extension, and
`pygments-citry`, the syntax highlighter for Pygments, reach 1.0.0 at
the same time.

## What "stable" means

From now on, an upgrade within 1.x keeps what the docs describe
working, with a few exceptions the Versioning page lists. In short:

- **Patch releases** (1.0.1) fix bugs.
- **Minor releases** (1.1.0) add features. A deprecated feature keeps
  working, with a warning, at least until 2.0.0.
- **Only 2.0.0** may remove or break what 1.x documents, apart from
  experimental features and fixes that close a security hole.
- **While you upgrade servers one at a time** between two 1.x releases,
  an open page may need one reload.

The [Versioning and support](/about/versioning/) page has the exact
rules: what each kind of release may change, what counts as a breaking
change, and how to pin Citry.

## What 1.x covers

The 1.x rules cover what the docs teach: the public Python names, the
template syntax, settings and extension hooks, the `citry` command line,
the browser JavaScript API, and the `citry-events/1` protocol that server
events use. See
[What the promise covers](/about/versioning/#what-is-covered) for the
full list.

A few features work and are tested, but their design is not settled yet,
so they are marked experimental and may change in a minor release. They
include component previews, the template analysis API (the code behind
`citry check` and the editor), and calling event handlers from your own
server code with `EventsDispatcher`. They are listed under
[Experimental features](/about/versioning/#experimental).

The [UI library](/ui-library/) is not covered. citry-ui stays on 0.x as
an alpha, so pin one minor release, such as `"citry-ui>=0.6.0,<0.7"`.

## Upgrade to 1.0.0

Citry 0.9.0 made the last large set of breaking changes, so the upgrade
is small. Upgrade to 0.9.x first and follow its upgrade notes, then
upgrade to 1.0.0.

1.0.0 adds one more breaking change. Citry sends each component's State
(the values its event handlers need between calls) to the page as a
signed string, the State token. For a component that sets no
`_max_age`, the token now stops working 24 hours after Citry issues it.
A call made with an expired token does not run its handler, and Citry's
browser code asks the visitor once whether to reload. Set a longer
`_max_age` on the component to change the lifetime.

[Upgrade to Citry 1.0.0](/guides/upgrading-to-1-0-0/) walks through
every step, and the
[changelog](https://github.com/citry-dev/citry/blob/citry@1.0.0/CHANGELOG.md){: target="\_blank" rel="noopener"}
lists every change.

## Which versions get fixes

0.x releases get no more fixes. Bug and security fixes go to the newest
1.x minor release, so stay current within 1.x. When 2.0.0 comes out,
the last 1.x minor release gets security fixes for 12 months.
