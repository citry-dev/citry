I've been waiting to write this post for a long time.

Two to three years ago I worked on a Django web app. When building the frontend,
there were two options:

1. **Django or Jinja templates**

    Simple and easy to pick up, but with no type checking and no isolation
    between components. Mistakes were easy to make, and you found them
    when someone opened the page.
    
2. **Separate JavaScript frontend in Vue or React**

    Great tooling and developer experience. But now you had two projects
    to manage, the Python one and the JavaScript one.

There were projects that tried to make the Python frontend experience
less frustrating - ReactPy, Reflex, FastHTML... - and they succeeded
to varying degree.

But it was still a far cry from the ease of development I knew from working
with Vue (and React) for many years:

- Easy to reason about components thanks to isolation and having everything in a single file.
- Smart IDE integration that understands my components, their inputs, etc.
- Linter catching errors during development.
- And much, much more...

Those ~3 years ago I started helping on out django-components (created by Emil Stenström), a Django
plugin that offered a component-like experience for templates.

Fast forward, and the new library, Citry, now fills that gap I missed. You now get high-end
frontend tooling, the kind Vue and React developers take for granted,
in a single Python codebase.

With v1, Citry is now ready to be used in production.

the best it can be. [See the roadmap](https://github.com/citry-dev/citry/issues/79){: target="\_blank" rel="noopener"}.

## What Citry is

A Citry component is a Python class. It holds its HTML template, its
browser behavior (in Vue), its CSS, its translations, and the Python
methods that run when the visitor clicks or submits something. One
component, one file, one codebase. No separate frontend project.

Here's a like button that runs Python when you click it:

```citry
from citry import Component

class LikeButton(Component):
    class Kwargs:
        product_id: int
        likes: int = 0

    class State(Kwargs):
        pass

    class Events:
        def like(self, state: LikeButton.State):
            save_like(state.product_id)
            return LikeButton(
                product_id=state.product_id,
                likes=state.likes + 1,
            )

    def template_data(self, kwargs: Kwargs, slots):
        return {"likes": kwargs.likes}

    template = """
      <button type="button" @c-click="like">
        Like ({{ likes }})
      </button>
    """

    css = """
      button {
        border-radius: 8px;
      }
    """
```

The click calls `like()` on the server, and Citry swaps in the new
button. No JavaScript to write, no API endpoint to add.

It runs with FastAPI, Django, Flask, Starlette, or any ASGI or WSGI app,
on Python 3.11 to 3.15.

## Safe from the start

Security is a huge problem these days because of AI.

A new framework simply doesn't have the accumulated knowledge of an established one.

But while AI is speeding up the rate of cyber threats, it's also speeding up
the rate at which we can protect ourselves.

To make Citry reasonably battle-tested from day one, I turned to the wider
frontend ecosystem, and audited Citry against all their known vulnerabilities. 

456 security advisories that other frameworks published - Django, Next.js,
Nuxt, React and Vue among them - and checked Citry for every kind of bug
that could apply to it. [How we check advisories](/security/#how-we-check)
walks through the process.

To handle new vulnerabilities, a monthly cron job checks for new ones.

See [Security](/security/) for practical details and limitations.

## Fast

Citry is fast. Really fast.

In our own test, a page with 1,400 entries was usable in 257 ms on its
second load. That's ahead of Next.js (324 ms) and of the Django stack
with django-components (475 ms), and just behind Nuxt (230 ms). All
from one Python codebase.

I wrote the same app in Citry and in eleven

## Smart

This is the part I missed most from Vue and TypeScript: tools that
understand your code and tell you about a mistake the moment you make
it.

In Django templates, mistakes stay quiet. Misspell a variable and the
page renders an empty spot. Pass a wrong input to a component and
nothing complains. You find out only when someone opens the page, or
when a customer tells you - and that's already too late.

In Citry, every component spells out what it takes, and Citry checks
every template against it. Your editor knows your components too. It
suggests their inputs as you type, shows their types when you hover,
and jumps from a template straight to the Python definition. A typo gets
underlined right away.

The same checks can be run in CI, to ensure you never ship a mistake.
Just call `citry check`.

This matters even more now that AI writes a big part of our code. An
AI agent makes the same small mistakes we do, just faster. When the
framework catches them, the agent sees the error and fixes it itself,
before you ever review the code.

## Versioning and support

Citry now follows SemVer - what the docs describe keeps working throughout 1.x
releases.

django-components has now entered the maintenance mode. It will receive updates
to remain compatible with supported Python and Django versions.

The [UI library](/ui-library/), citry-ui, is still in development, so pin one
minor release, such as `"citry-ui>=0.6.0,<0.7"`. The exact rules are
in [Versioning and support](/about/versioning/).

## Coming from django-components?

You don't have to move everything at once:
[citry-django](https://github.com/joeyjurjens/citry-django){: target="\_blank" rel="noopener"},
a community project by Joey Jurjens, lets Citry components and your
existing Django templates live side by side, so you can migrate one
component at a time. The [migration guide](/guides/migrate-from-django-components/) shows what changes.

## Upgrading from earlier versions

**Citry:**

1. Upgrade to the newest 0.9.x and follow its upgrade notes.
2. Upgrade to 1.0.0: `pip install -U citry`.

Step by step: [Upgrade to Citry 1.0.0](/guides/upgrading-to-1-0-0/).

**VSCode extension:**

`citry-lsp`, the VS Code extension and `pygments-citry` are at 1.0.0
too; upgrade `citry-lsp` and the extension together.

**Citry UI:**

citry-ui 0.6.0 needs Citry 1.0.0 or later.
